## 修正した不具合

| 問題 | 再現条件と影響 | 修正・検証 |
|---|---|---|
| CAP/SAMの削除未確認 | Destroyがnilで戻っても実体が残る。参照を解放すると敵が残留し、削除を再試行できない | Destroy後にnative実体を再取得して消失確認。失敗は元の所有者に保持。REL-01/02 |
| 生成途中の敵残留 | Intercept/CAP/SEADでnative生成後に例外/nil。SAMでは生成後設定失敗＋初回削除失敗も参照を失う | 任務固有aliasの#001をMOOSE/nativeから回収。独立した待ちで5秒再試行。任務ロック解放後に採点しない。REL-03/12/18 |
| 死亡時のID未照合 | Strike/SEAD/DEAD/Siteの一部でIsAlive=falseをID照合より先に採用。別IDの死亡が元の目標達成・Site全滅になる | 全カテゴリで固定IDの観測契約を共通化。他IDは不明として待つ。明示死亡＋ID消失だけは死亡wrapperとして許容。REL-04〜06 |
| 帰還の観測失敗 | 例外後に以前の停止時刻が残る。NaN位置/速度やInAir=nilで帰還成功する。同Wingの先頭の例外で僚機評価も止まる | 有限Vec3・boolean・基地所属・空母IDを検査。異常は参加者単位で封じ込め、停止計測を再開。基地所属不明では着地文脈を保持。REL-07〜11/13 |
| 監視されていない時間の加算 | 帰還/抑制を一度観測後、監視が10/30秒途切れて復旧すると連続時間達成になる | 観測間隔がpollSecondsの2倍超、または時計逆行で計測を再開。正常1秒監視時は10/30秒を維持。REL-16/17 |
| 不正地形値での配置承認 | NaN/Infinity地表高、NaN障害物位置/水平boundsで大小比較が成立せず危険な地点を通す | 不正値は観測不能として配置を中断し、既存の安全な解除経路へ戻す。REL-14/15 |

生死不明を自動死亡に置き換えず、削除不明を削除成功に置き換えない。明示的に照合できた喪失イベントは引き続き優先する。

## 再利用性・構造の整理

- `observations.lua`: 有限数・Vec3、固定IDの生死観測、連続時間の境界を共通化した。目標数・達成条件・表示・採点は各任務に残した。
- `object_lifecycle.lua`: Destroyの返り値と実体消失を区別する処理、固有Group aliasの回収、部分生成の削除待ちを共通化した。
- Intercept/CAPの通常削除、SAMの保持/使用予約、Strike/車列の地域予約は元のモジュールが所有する。共通削除待ちへ全Siteを移すと所有権が曖昧になるため、削除確認だけを共有する。
- 帰還の例外処理を参加者の境界へ移した。1人の観測失敗で同Wing全体の精算が止まらない。
- 配置専用ミッションは通常mainを差し替えるため、部分生成の削除待ちも独自のmission timerで掃除するようにした。

MEのZone・テンプレート名、受注ルール、通常メッセージ、PB/TOO抽選、150/90/0、保存schema4は維持した。serverコードと保存Hookの内容は変更していない。

## 維持した設計判断

| 判断 | 理由 |
|---|---|
| main.luaは調整役として残す | 約920行で受注・イベント・精算の結合点を明示している。汎用FSMへの全面置換はImmediate DEADや個別精算の順序を複雑にし、今回の不具合の原因でもない |
| 任務状態・参加者状態・Site方針を別に持つ | 「SEAD達成」と「Site全滅」、「1人帰還」と「Wing終了」は同じ寿命ではない |
| Site/地域予約を各所有者に残す | 削除未確認中の再生成と、元Wingの保持予約を守る必要がある |
| Statusは保存した公開本文を返す | 見返す操作が生存数やレーダー状態を新たに公開したり、達成・精算を進めたりしない |
| 成績の保存確認をACKで分ける | ミッション側の精算とディスク保存は別の完了条件。I/O失敗を保存成功と表示しない |
| 二重精算防止台帳を保持する | 古いイベント/再試行に対する冪等性を保つ。安易な削除は二重加点を再導入する |

## 残る課題と確認の限界

1. **実サーバーの長時間測定**: 模擬120任務は、DCS/MOOSE内部のオブジェクト寿命や性能を保証しない。採点台帳は任務数と共に増える設計で、MOOSEの登録済みwrapperも別に存在する。実機の任務数・メモリ・ログを測定してから、必要なら寿命管理を設計する。
2. **実ゲーム固有の挙動**: SAM地形/抑制、AI交戦、移動車列の道路・橋・散開復帰、建物の耐久・信管、PBのPP入力、煙の視認性、移動空母着地を確認する。保存済み配置の静的検証で置き換えない。
3. **mainの今後の拡張**: カテゴリを増やす際は受注準備・終了調整の単位で分離する。現在の受注rollback、イベント順序、全員終了、古いcallback拒否を結合テストで維持する。今の規模で継承階層・汎用plugin registryは導入しない。
4. **意図した仕様上の制限**: 第三者の撃破も対象破壊に数える。進行中任務・Siteは再起動後に復元せず、永続化するのは精算済み成績。静的ClientのBLUE Hornetが対象で、Apache・動的スロット・複数乗員は別設計が必要。
5. **保証対象外**: 新しいDCS/MOOSE版の互換性、OSの物理fsync、複数hostからの同時保存、未知のイベント/API挙動。修正後に「バグがない」とは断定しない。
