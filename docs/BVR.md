# BVR 訓練ミッション仕様

更新日: 2026-10-04

## 目的と対象範囲

プレイヤーの現在位置と機首方向を基準に敵戦闘機を生成し、
BVR（目視外距離）での接敵・交戦を訓練する。
空港や出撃地点を固定せず、地上で要求した場合は離陸後に生成する。

この文書は現在のコードの動作、既知の制約、将来の仕様を区別して記載する。
「実装済み」はソースに処理があることを示し、DCS 内での動作確認完了を意味しない。
全体の開発方針は [AGENTS.md](../AGENTS.md) に従う。

## 操作と開始条件（実装済み）

F10 メニュー: `Dynamic Training → Generate BVR`

| 選択時の状況 | 動作 |
|---|---|
| 実行中 | `A BVR mission is already active.` を表示し、追加生成しない |
| 離陸待ち / 20秒の生成待ち | `BVR mission is already armed.` を表示し、追加予約・生成しない |
| BLUE プレイヤーを取得できない | `Player aircraft not found.` を表示する |
| プレイヤーが空中 | その時点の位置・機首方向で即時スポーンする |
| プレイヤーが地上 | 離陸待ちにし、`BVR mission armed.` を表示する |

地上からの離陸待ちは2秒間隔で `InAir()` を確認する。
空中になったことを検出すると `Takeoff detected. Hostiles will spawn in 20 seconds.` を表示し、
検出から20秒後に、生成時点の位置・機首方向を基準にスポーンする。
実際の離陸から生成までは、検出の遅れを含めて約20～22秒。
離陸イベントの購読ではなく、定期監視で判定する。
生成前に着地するとカウントをリセットし、次の離陸検出から再び20秒待つ。
予約時の機体・DCS オブジェクト ID・プレイヤー名を保持し、死亡・離脱・機体変更・操縦者変更時は予約を解除する。
AI 僚機や別プレイヤーの離陸で予約を発動しない。

現在のプレイヤー取得は `coalition.getPlayers(BLUE)` の先頭1機を MOOSE の `UNIT` に変換する。
F10 を選択した本人の取得や、機種・スロットの絞り込みは実装していない。
本仕様の現行動作は、BLUE プレイヤー1名での使用を前提とする。

## 敵生成と経路（実装済み）

| 項目 | 現在の値 / 動作 |
|---|---|
| 敵編成 | テンプレートの MiG-29A ×2、1編隊 |
| 初期距離 | 60～80 NM の整数からランダム。水平距離 |
| 生成方位 | プレイヤーの機首方向から左右60°以内。-60～+60°の整数からランダム。基準は地上航跡ではなく機首方向 |
| 初期高度 | 15,000～30,000 ft の整数からランダム。BARO / 海面基準 |
| Aspect | HOT。敵の生成位置から、生成時のプレイヤー位置へ向く方位を設定 |
| 経路終点 | 生成時のプレイヤー位置から、敵の出現方向と反対へ20 NM。ランダム化した接近経路の延長上 |
| 経路高度 | 敵の生成高度を維持 |
| 指定速度 | 230 m/s（約447 knots） |
| 交戦対象 | AI が探知した敵の `Fighters` / `Multirole fighters`。BLUE AWACS を対象に含めない |
| 交戦規則 | Open Fire（指定対象のみ）。Weapons Free は使用しない |
| 位置更新 | 生成時に一度設定。プレイヤーの移動を追跡して更新しない |

距離と座標は編隊の基準点についての値で、各機の位置にはテンプレートの編隊間隔が加わる。
高度はプレイヤー高度に対する相対値や地上高ではない。
経路はプレイヤーの生成時の水平位置を通過する線となり、高度まで一致させるものではない。

### 座標計算

同梱 MOOSE の `POSITIONABLE:GetHeading()` は `atan2(機首ベクトル.z, 機首ベクトル.x)` を使う。
水平面で0°は `+x`、90°は `+z` と定義される。
プレイヤーの座標を `P`、機首方向を `H` [度]、ランダムな方位差を `δ` [度] とすると、
次の式で求める。実装には MOOSE の座標 API を使用する。

```text
δ = -60～+60 のランダムな整数
B = (H + δ) % 360  # 敵の出現方位[度]
b = B × π / 180
出現方向の単位ベクトル F = (cos(b), sin(b))  # (x, z)

敵生成位置:
  x = P.x + cos(b) × 距離[m]
  y = 敵高度[m]
  z = P.z + sin(b) × 距離[m]

経路終点:
  x = P.x - cos(b) × 20 × 1852
  y = 敵高度[m]
  z = P.z - sin(b) × 20 × 1852

敵機首方向[度] = 生成位置から P へ向く方位
                 = (B + 180) % 360
```

単位変換は `1 NM = 1852 m`、`1 ft = 0.3048 m`。

次の表は方位差 `δ = 0°` の場合を示す。方位差がある場合は出現方位 `B` に合わせて回転する。

| 機首方向（δ = 0°） | 生成位置の方向 | 経路終点の方向 |
|---|---|---|
| 0° | +x | -x |
| 90° | +z | -z |
| 180° | -x | +x |
| 270° | -z | +z |

2026-10-04 に生成位置と経路終点の両方の `sin` / `cos` を修正した。
45°だけでは旧式との差が出ないため、検証には他の方位も含める。

その後、機首方向から左右60°の方位ランダム化を追加した。
生成位置は `COORDINATE:Translate(distanceM, spawnBearing, true)`、
敵機首は `spawnCoordinate:HeadingTo(playerCoordinate)` で計算する。
経路終点も `spawnBearing + 180°` に沿って平行移動し、生成時のプレイヤー水平位置を通る直線を保つ。
`SetAltitude(altitudeM, true)` の `true` は ASL の指定で、高度を地上高に変えないために必要。

生成は `SPAWN:New(...):InitHeading(...):SpawnFromVec3(...)` を使用する。
`ConfigureBVRRoute` が生成位置と経路終点の2つのウェイポイントを作成し、
最初のウェイポイントに `EnRouteTaskEngageTargets(nil, {"Fighters", "Multirole fighters"}, 0)`
で作った攻撃指示を組み込む。移動と攻撃指示をまとめて `GROUP:Route(...)` へ渡す。
テンプレートの全航空機向け CAP タスクは、この訓練用の交戦対象を限定したタスクへ置き換える。

ウェイポイントは `WaypointAirTurningPoint` / `WaypointAirFlyOverPoint` で作成する。
両 API の速度単位は km/h のため、230 m/s を `× 3.6` で828 km/hに変換して渡す。
`Route` の標準動作により、タスクの適用は約1秒遅延する。

`OptionROEOpenFire()` で指定対象への攻撃だけを許可する。
`Weapons Free` ではフィルター外の航空機にも攻撃できるため使用しない。
プレイヤー名を指定した強制攻撃や、探知前の目標情報の注入は行わない。
攻撃開始・発射タイミングは AI の探知、兵装、射程等に依存する。
`EngageTargets` の距離引数は経路からの対象の距離制限であり、発射距離ではない。
現行実装は `nil` を渡し、その制限を設定しない。

HOT の初期配置、攻撃指示の構成、実際の探知・交戦動作はそれぞれ確認する。

## 状態と完了判定（実装済み）

状態は `src/DynamicTraining.lua` 内の以下の変数で管理する。
ミッションは BLUE 全体で同時に1件で、プレイヤーごとの状態ではない。

| 文書上の状態名 | bvrPending | bvrSpawnAt | bvrActive | currentEnemyGroup |
|---|---|---|---|---|
| 待機 | false | nil | false | nil |
| 離陸待ち | true | nil | false | nil |
| 生成待ち | true | 離陸検出時刻 + 20秒 | false | nil |
| 実行中 | false | nil | true | スポーンした GROUP |

予約中は `bvrPendingPlayer` に機体・ID・プレイヤー名を保持する。予約解除時にすべてクリアする。

待機から空中で要求すると実行中へ、地上で要求すると離陸待ちへ遷移する。
離陸検出時に生成待ちへ遷移し、20秒後に予約を解除して生成する。
スポーン成功後に実行中へ遷移する。
敵グループの `IsAlive()` が真でなくなった場合、2秒間隔の監視が待機状態へ戻し、
`BVR MISSION COMPLETE / All hostile aircraft destroyed.` を15秒間表示する。
その後は次の BVR を生成できる。

現行の完了判定は「敵グループが生存しているか」の確認に限る。
各機の撃墜イベント・撃墜者・消滅理由を記録しないため、全機をプレイヤーが撃墜したことまでは保証しない。
Primary Objective Complete と RTB 評価を分ける状態はまだ実装していない。

## 表示とエラー処理

開始時は BLUE 全体に15秒間、敵編成・距離（NM）・高度（ft）・HOT aspect を表示する。
距離・高度は生成時の設定値で、現在の相対距離を継続表示するものではない。
敵を探す訓練のため、今回追加した正確な出現方位・方位差は開始メッセージに表示しない。

| ケース | 現行動作 / 制約 |
|---|---|
| `SpawnBVR` に無効・生存していないプレイヤーを渡した | プレイヤー不在メッセージを表示し、生成しない |
| スポーンの戻り値が nil | `ERROR: BVR enemy spawn failed.` を15秒間表示し、実行中にしない |
| 20秒後にスポーン失敗 | 予約は解除済み。再度 `Generate BVR` を選択する |
| 予約中のプレイヤー死亡・離脱・機体変更・操縦者変更 | 予約を解除し、取消メッセージを表示する |
| 生成待ち中の着地 | カウントをリセットし、離陸待ちへ戻る |
| 予約中の別プレイヤーの参加・僚機の離陸 | 予約した機体を引き続き監視する |
| 地上に留まり続ける | 離陸待ちを継続する。タイムアウトはない |
| 実行中のプレイヤー死亡・離脱 | 中断・失敗判定や敵の後片付けはない |
| MOOSE 未読み込み、テンプレート不在、API の例外 | 保護呼び出し・統一エラーログは未実装。DCS ログで確認する |

## 動作確認項目

以下は DCS / ME 内で実施する。現時点では、MOOSE 読み込みと F10 メニュー表示が確認済み。
20秒の生成待ち・座標修正・方位ランダム化・経路への攻撃指示追加を含め、生成・経路・交戦・完了判定のゲーム内確認は未実施として扱う。

`scripts/Test-BVR.lua` は実際のミッションスクリプトを Lua 5.1 で読み込み、DCS / MOOSE の呼び出し先を模擬する。
生成のタイミング・予約の解除とリセット・重複抑止・生成時点の位置・距離と方位の境界・経路の構成を自動検証する。
この検証はゲーム内の離陸判定や AI 交戦の確認を代替しない。

| ケース | 期待結果 |
|---|---|
| 地上で生成要求 | 敵を即時生成せず、離陸待ちメッセージを表示する |
| 離陸待ち / 生成待ち中に再要求 | 予約が1件のままで、カウントを変更せず追加生成しない |
| 離陸 | 約2秒間隔の監視で検出し、20秒間は生成せず、その後に1編隊を生成する |
| 20秒の間に移動・旋回 | 生成時点の位置・機首方向を基準に生成する |
| 生成前に着地して再離陸 | カウントをリセットし、再離陸検出から20秒後に生成する |
| 予約中に死亡・離脱・スロット変更 | 予約を解除し、別機体で勝手に生成しない |
| AI 僚機だけが離陸 | プレイヤーが地上にいる間は離陸待ちを維持する |
| 空中で生成要求 | 離陸待ちを挟まず生成する |
| 機首方位 0 / 90 / 180 / 270° と斜め方向 | 敵が機首方向から左右60°以内に出現し、距離が60～80 NMに収まる |
| 方位差 -60 / 0 / +60° と 0 / 360° 境界 | 方位が正規化され、左右60°の制限と HOT を維持する |
| 敵初期姿勢と経路 | ランダムな出現方位でも機首がこちらを向き、生成時のプレイヤー水平位置を通って出現方向の反対側20 NMへ進む |
| 高度・速度 | 15,000～30,000 ft BARO、経路指定速度が約447 knots |
| 実行中に再要求 | 敵が二重生成されない |
| 敵1機だけ撃墜 | 完了表示が出ず、残機が生存している |
| 敵全滅 | 監視で完了表示し、次の生成が可能になる |
| AI 交戦 | ME の兵装と経路タスクを確認し、敵が探知・接敵・発射することを確かめる |
| AWACS の除外 | 敵が Hornet に交戦し、BLUE E-3A を攻撃対象として追跡・攻撃しない |
| プレイヤーの再武装 | 地上で再武装を要請し、選択した兵装を搭載できる |
| 4つの BLUE スロットを個別使用 | 出撃空港によらず現在のプレイヤーを基準に開始する |
