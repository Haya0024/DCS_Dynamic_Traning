# Intercept 訓練ミッション仕様

更新日: 2026-10-05

## 目的と対象範囲

プレイヤーの現在位置と機首方向を基準に敵戦闘機を生成し、
Intercept（迎撃）任務として、目視外距離での接敵・交戦を訓練する。
空港や出撃地点を固定せず、地上で要求した場合は離陸後に生成する。

この文書は現在のコードの動作、既知の制約、将来の仕様を区別して記載する。
「実装済み」はソースに処理があることを示し、DCS 内での動作確認完了を意味しない。
全体の開発方針は [AGENTS.md](../AGENTS.md) に従う。

## 実行環境と Mission Editor の前提

| 項目 | 設定 |
|---|---|
| シミュレーター / マップ | DCS World / Syria |
| フレームワーク | MOOSE。DynamicTraining より先に読み込む |
| BLUE | USA、F/A-18C Lot 20 の Client スロット |
| RED | Russia |
| 敵テンプレート名 | `TPL_INT_MIG29A_2`、`TPL_INT_SU27_1`、`TPL_INT_MIG29A_1` |
| 敵テンプレート構成 | 順に MiG-29A ×2、Su-27 ×1、MiG-29A ×1。すべて Late Activation、Airborne Start、CAP |
| 現在の敵 AI Skill | テンプレートの `High` を継承 |

任務の名称は Intercept。生成候補は ME に登録した `TPL_INT_...` のグループ名を参照する。
ME で名前を変更したら `intercept.templates` と仕様書も合わせる。同期処理で ME のグループ名は変更しない。

BLUE は空港・空母に複数のスロットを配置している。単独用グループの例は以下。
実装はグループ名や空港名を指定して検索しない。

- `BLUE_HORNET_INCIRLIK_01`
- `BLUE_HORNET_AKROTIRI_01`
- `BLUE_HORNET_BEIRUT_01`
- `BLUE_HORNET_RAMAT_01`

単独用は Client と AI 僚機の構成。MP2 は Client ×2 で、
`BLUE_HORNET_INCIRLIK_MP2_01`、`BLUE_HORNET_AKROTIRI_MP2_01`、`BLUE_HORNET_BEIRUT_MP2_01`、
`BLUE_HORNET_RAMAT_MP2_01`、`BLUE_HORNET_SC_MP2_01` を配置済み。
初期パイロンが空のプレイヤースロットは、意図した再武装運用として扱う。
プレイヤーが地上で再武装を要請し、訓練に合わせて好きな兵装を搭載する。
スクリプトでプレイヤー兵装を固定せず、空の初期設定を不備として扱わない。
現在の敵テンプレートは MiG-29A 各機に6ステーション、Su-27 に10ステーションの兵装設定がある。
同期ツールは兵装やその他のミッション設定を変更しない。

BLUE 支援機として `BLUE_AWACS_OVERLORD`（E-3A / Overlord）が ME に配置されている。
251 MHz、30,000 ft BARO、Race-Track の周回設定と AWACS / EPLRS タスクがある。
スクリプトによる動的生成ではない。無線・データリンクのゲーム内動作は別途確認する。

BLUE 空母 `Naval-1`（艦名 `Naval-1-1`、ME 内の機種は `Stennis`）も配置されている。
同期時に空母・僚機・プレイヤースロットの設定を保持する。

## 操作と開始条件（実装済み）

F10 メニュー: `Dynamic Training → Generate Intercept`

メニューは BLUE Hornet のプレイヤーグループごとに表示する。`Mission Status`、`Abort Mission`、
`Player Statistics` も実装済み。接続中のプレイヤーを2秒間隔で検出する。

| 選択時の状況 | 動作 |
|---|---|
| 実行中 / 帰還待ち / 着陸確認中 | 既存任務があることを表示し、追加生成しない |
| 離陸待ち / 20秒の生成待ち | `Intercept mission is already armed.` を表示し、追加予約・生成しない |
| 対象グループに人間がいない | 参加者不在を表示し、生成しない |
| 全参加者が空中 | 長機のその時点の位置・機首方向で即時スポーンする |
| 地上の参加者がいる | 全員の離陸待ちにし、`Intercept mission armed.` を表示する |

地上からの離陸待ちは2秒間隔で `InAir()` を確認する。
全参加者が空中になったことを検出すると `All registered pilots airborne. Hostiles will spawn in 20 seconds.` をデバッグログへ記録し、
検出から20秒後に、生成時点の長機位置・機首方向を基準にスポーンする。
全参加者の実際の離陸から生成までは、検出の遅れを含めて約20～22秒。
離陸イベントの購読ではなく、定期監視で判定する。
生成前に着地するとカウントをリセットし、次の離陸検出から再び20秒待つ。
予約時の UCID・機体・DCS オブジェクト ID・表示名を保持し、死亡・離脱・機体変更・操縦者変更時は予約を解除する。
AI 僚機や未参加者の離陸で予約を発動しない。

F10 の対象グループ内の人間プレイヤー全員を受注時に登録する。BLUE / `FA-18C_hornet` を対象とする。
空席・AI は登録しない。途中参加者は次の任務から参加する。
長機の基準は搭乗中の参加者の機体番号が最も小さい機体。1人だけでも受注できる。
UCID はサーバー接続情報の名前・陣営・静的 Client スロットを照合して取得し、成績のキーにする。
UCID が取得できない場合は非採点の訓練として実行する。
MP2 の同じグループで目標を共有する。任務はウィングごとに同時に1件で、別ウィングは並行して受注できる。
操作と受注ブロックの詳細は [WING.md](WING.md) を参照する。

## 敵生成と経路（実装済み）

この節の「プレイヤー位置・機首方向」は、生成の基準となる長機の値を指す。

| 項目 | 現在の値 / 動作 |
|---|---|
| 敵編成 | MiG-29A ×2 / Su-27 ×1 / MiG-29A ×1 から生成ごとに各1/3の確率で1編成 |
| 編隊形状 | WEDGE / LINE_ABREAST / TRAIL / ECHELON_LEFT / ECHELON_RIGHT から生成ごとに等確率で1種類 |
| 編隊間隔 | MOOSE 固定翼の Open。`src/config.lua` の `formationSpacing` で変更可能 |
| 初期距離 | 60～80 NM の整数からランダム。水平距離 |
| 生成方位 | プレイヤーの機首方向から左右60°以内。-60～+60°の整数からランダム。基準は地上航跡ではなく機首方向 |
| 初期高度 | 15,000～30,000 ft の整数からランダム。BARO / 海面基準 |
| Aspect | HOT。敵の生成位置から、生成時のプレイヤー位置へ向く方位を設定 |
| 経路終点 | 生成時のプレイヤー位置から、敵の出現方向と反対へ20 NM。ランダム化した接近経路の延長上 |
| 経路高度 | 敵の生成高度を維持 |
| 指定速度 | 230 m/s（約447 knots） |
| 交戦対象 | AI が探知した敵の `Fighters` / `Multirole fighters`。BLUE AWACS を対象に含めない |
| 交戦規則 | Open Fire（指定対象のみ）。Weapons Free は使用しない |
| 位置更新 | 生成時に一度設定。プレイヤーの移動を追跡して更新しない |

距離と座標は編隊の基準点についての値で、各機の位置にはテンプレートの編隊間隔が加わる。
生成直後の相対配置はテンプレートから継承し、その後 AI が選択された編隊形状へ移行する。
高度はプレイヤー高度に対する相対値や地上高ではない。
経路はプレイヤーの生成時の水平位置を通過する線となり、高度まで一致させるものではない。

### 敵テンプレートのランダム化

`src/config.lua` の `intercept.templates` に ME のグループ名を列挙し、
実際の生成時に `math.random(1, #templates)` で1つ選ぶ。予約時にはまだ抽選しない。
候補は編成単位で等確率。MiG-29A の2編成と Su-27 の1編成があるため、機種単位では MiG-29A が2/3、Su-27 が1/3となる。
連続して同じ編成になることもある。別ウィングや次の任務は個別に抽選し、二重受注の拒否では再抽選しない。

機種・機数・兵装・Skill は選んだ ME テンプレートを継承する。
デバッグ開始ログの敵編成は、生成した各機の `UNIT:GetTypeName()` と実際の機数から作る。
全滅判定も生成した機体一覧に基づき、1機編成ではその1機、2機編成では両機の喪失が必要。
どの編成でも報酬は現在の固定設定どおり、帰還成功150ポイント・クリア後の事故90ポイント。
候補一覧が空、選んだテンプレートが不在、生成や経路設定に失敗した場合は、エラーを記録して受注ロックを解除する。
再要求で新しく抽選する。別候補への自動再抽選はしない。

### 座標計算

同梱 MOOSE の `POSITIONABLE:GetHeading()` は `atan2(機首ベクトル.z, 機首ベクトル.x)` を使う。
水平面で0°は `+x`、90°は `+z` と定義される。
プレイヤーの座標を `P`、機首方向を `H` [度]、ランダムな方位差を `δ` [度] とすると、
次の式で求める。実装には MOOSE の座標 API を使用する。

```text
δ = -60～+60 のランダムな整数
B = (H + δ) % 360  # 敵の出現方位[度]
b = B × π / 180
出現方向の単位ベクトル F = (cos(b), sin(b))  # (x, z)

敵生成位置:
  x = P.x + cos(b) × 距離[m]
  y = 敵高度[m]
  z = P.z + sin(b) × 距離[m]

経路終点:
  x = P.x - cos(b) × 20 × 1852
  y = 敵高度[m]
  z = P.z - sin(b) × 20 × 1852

敵機首方向[度] = 生成位置から P へ向く方位
                 = (B + 180) % 360
```

単位変換は `1 NM = 1852 m`、`1 ft = 0.3048 m`。

次の表は方位差 `δ = 0°` の場合を示す。方位差がある場合は出現方位 `B` に合わせて回転する。

| 機首方向（δ = 0°） | 生成位置の方向 | 経路終点の方向 |
|---|---|---|
| 0° | +x | -x |
| 90° | +z | -z |
| 180° | -x | +x |
| 270° | -z | +z |

2026-10-04 に生成位置と経路終点の両方の `sin` / `cos` を修正した。
45°だけでは旧式との差が出ないため、検証には他の方位も含める。

その後、機首方向から左右60°の方位ランダム化を追加した。
生成位置は `COORDINATE:Translate(distanceM, spawnBearing, true)`、
敵機首は `spawnCoordinate:HeadingTo(playerCoordinate)` で計算する。
経路終点も `spawnBearing + 180°` に沿って平行移動し、生成時のプレイヤー水平位置を通る直線を保つ。
`SetAltitude(altitudeM, true)` の `true` は ASL の指定で、高度を地上高に変えないために必要。

生成は `SPAWN:NewWithAlias(...):InitHeading(...):SpawnFromVec3(...)` を使用する。
受注番号を含む別名で敵を生成し、別任務とのグループ名・機体名の衝突を防ぐ。ME のテンプレート名は変更しない。
`src/intercept.lua` の `Intercept.Spawn` が生成位置と経路終点の2つのウェイポイントを作成し、
最初のウェイポイントに `EnRouteTaskEngageTargets(nil, {"Fighters", "Multirole fighters"}, 0)`
で作った攻撃指示を組み込む。移動と攻撃指示をまとめて `GROUP:Route(...)` へ渡す。
テンプレートの全航空機向け CAP タスクは、この訓練用の交戦対象を限定したタスクへ置き換える。

ウェイポイントは `WaypointAirTurningPoint` / `WaypointAirFlyOverPoint` で作成する。
両 API の速度単位は km/h のため、230 m/s を `× 3.6` で828 km/hに変換して渡す。
`Route` の標準動作により、タスクの適用は約1秒遅延する。

`OptionROEOpenFire()` で指定対象への攻撃だけを許可する。
`Weapons Free` ではフィルター外の航空機にも攻撃できるため使用しない。
プレイヤー名を指定した強制攻撃や、探知前の目標情報の注入は行わない。
攻撃開始・発射タイミングは AI の探知、兵装、射程等に依存する。
`EngageTargets` の距離引数は経路からの対象の距離制限であり、発射距離ではない。
現行実装は `nil` を渡し、その制限を設定しない。

HOT の初期配置、攻撃指示の構成、実際の探知・交戦動作はそれぞれ確認する。

### 編隊形状のランダム化

`src/config.lua` の `intercept.formations` に候補を置き、生成ごとに1回 `math.random(1, #formations)` で選ぶ。
現在は5候補が各20%。ECHELON_LEFT と ECHELON_RIGHT は別の候補として扱う。
別ウィングの任務でも個別に選び、二重受注が拒否された場合は再抽選しない。

| 設定名 | MOOSE の固定翼設定 |
|---|---|
| WEDGE | `ENUMS.Formation.FixedWing.Wedge.Open` |
| LINE_ABREAST | `ENUMS.Formation.FixedWing.LineAbreast.Open` |
| TRAIL | `ENUMS.Formation.FixedWing.Trail.Open` |
| ECHELON_LEFT | `ENUMS.Formation.FixedWing.EchelonLeft.Open` |
| ECHELON_RIGHT | `ENUMS.Formation.FixedWing.EchelonRight.Open` |

`formationSpacing` は `Close` / `Open` / `Group` を指定でき、全候補に共通で適用する。
生成後に MOOSE `GROUP:SetFormation` で指示し、遅延して適用される経路の最初のウェイポイントにも
MOOSE `TaskWrappedAction` で編隊オプションを組み込み、同じ選択を反映する。
標準 DCS の編隊オプション識別子を使う理由はコードに記載する。
選択名と間隔は任務の生成記録と開始ログに残す。プレイヤー向け開始表示には追加しない。

これは AI の編隊指示で、スポーン時点の各機座標を選択形状へ瞬時に置き換える処理ではない。
MiG-29A ×2 では形状によって外見上の違いが小さくなる場合がある。
1機編成では編隊形状・間隔による外見上の違いはない。
交戦時には AI が編隊を崩すこともあるため、接敵前の状態でゲーム内の形状を確認する。
未対応の候補・間隔や設定失敗は生成失敗として処理し、生成済みの敵を削除して再要求を可能にする。

## 状態と完了判定（実装済み）

状態は `src/missions.lua` の `Missions.wings[groupName]` とその参加者一覧に集約する。
ウィングごとに同時に1任務で、別ウィングは独立して並行実行する。受注したウィングの参加者は固定し、帰還評価・報酬は参加者ごとに管理する。

| 状態 | 意味 |
|---|---|
| 当該ウィングの任務記録がない | 待機。搭乗者 UCID が別の未終了任務に紐づかなければ受注可能 |
| ARMED | 地上予約。全参加者の離陸待ち |
| TAKEOFF_DELAY | 離陸検出から20秒の生成待ち |
| ACTIVE | 敵生成済み。交戦中 |
| RTB_PENDING | 敵全滅。帰還待ち |
| LANDING_CHECK（参加者ごと） | BLUE 飛行場・空母への個別着陸確認中。共通状態は RTB_PENDING |
| RTB_SUCCESS / RTB_FAILURE / FAILED / ABORT（参加者ごと） | 各自の精算・中止済み |

敵は生成時に各機の DCS オブジェクトを記録し、死亡・墜落・機体喪失イベントで全滅を判定する。
補助的に1秒監視で生存状態を確認するが、未精算の元の参加者機が全機失われた後にクリアを推測しない。
敵全滅で `Intercept PRIMARY OBJECTIVE COMPLETE` と帰還指示を表示する。この時点ではポイントを加算しない。
各参加者が BLUE 飛行場・空母に帰還して条件を満たすと各自150ポイント、クリア後の墜落・死亡・脱出は該当者だけ90ポイントを付与する。
未クリアの事故・任意 Abort は該当者だけ0ポイント。長機の喪失・個人中止後も僚機は継続できる。
全員の精算・中止後に受注ロックを解除し、敵を削除して待機状態へ戻す。
1人だけ精算してもウィング名と登録 UCID のロックを維持する。別スロットへ移動しても新たな受注はできない。
登録者は別スロットから UCID を照合し、名前・機体を指定する個人 Abort で自分の出撃を中止できる。
僚機の撃墜も任務クリア条件に含む。個別の撃墜者・撃墜数はまだ採点しない。
詳細は [プレイヤー採点・帰還評価仕様](SCORING.md) を参照する。

## 表示とエラー処理

地上受注時は登録人数と全員の離陸待ちだけを通知する。全員離陸後の20秒待ちと着地によるカウントリセットは画面に出さず、DCSログの `[DEBUG]` に記録する。生成成功時は `Intercept MISSION START` とRange・Altitude・Aspect: HOTを15秒で1回表示する。Hostiles、Pilotsと各自の報酬はデバッグログのみ。通常の画面通知も同じ本文をDCSログへ記録する。実際の出力例は [MESSAGES.md](MESSAGES.md) を参照する。
開始通知は空中受注でも1回だけ出し、MP2両者の操作・離陸イベント・定期監視・メニュー再生成によって再掲しない。デバッグログにも開始情報と参加者・各自の報酬を記録する。
距離・高度は生成時の設定値で、現在の相対距離を継続表示するものではない。
敵を探す訓練のため、今回追加した正確な出現方位・方位差は開始メッセージに表示しない。

| ケース | 現行動作 / 制約 |
|---|---|
| 開始前にプレイヤーが無効・死亡・別機体へ移動 | 予約を解除し、生成しない |
| スポーンの戻り値が nil、または経路設定に失敗 | エラーを表示・記録し、生成した敵があれば削除して再要求を可能にする |
| 20秒後にスポーン失敗 | 予約は解除済み。再度 `Generate Intercept` を選択する |
| 予約中のプレイヤー死亡・離脱・機体変更・操縦者変更 | 予約を解除し、取消メッセージを表示する |
| 生成待ち中の着地 | カウントをリセットし、離陸待ちへ戻る |
| 予約中の途中参加・AI 僚機の離陸 | 受注時に登録した参加者だけを引き続き監視する |
| 地上に留まり続ける | 離陸待ちを継続する。タイムアウトはない |
| 実行中の墜落・死亡・脱出 | 該当者だけクリア済みなら60%、未クリアなら0ポイントで精算する。残る参加者は継続する |
| 実行中の退出・スロット変更 | 該当者だけ保留。元の機体への復帰または同じ UCID による個人 Abort が可能。自動60%にはしない |
| UCID 不明 | 訓練は可能だが採点なしと表示する |
| MOOSE 未読み込み、テンプレート不在、API の例外 | 読み込みエラーや保護呼び出しで表示・ログを残す。監視タイマーは可能な限り継続する |

## 動作確認項目

以下は DCS / ME 内で実施する。現時点では、MOOSE 読み込みと F10 メニュー表示が確認済み。
名称変更前の任務について、ユーザーからゲーム内で動作しているとの報告あり。
20秒の生成待ち・方位・敵テンプレート抽選・AI 交戦・UCID 採点・帰還評価の個別確認範囲は未記録。
Intercept への名称変更後のゲーム内表示は再確認する。

`scripts/Test-Intercept.lua`、`scripts/Test-Scoring.lua`、`scripts/Test-Wing.lua`、`scripts/Test-ParallelWings.lua` は結合済みの実際のミッションスクリプトを Lua 5.1 で読み込み、DCS / MOOSE の呼び出し先を模擬する。
生成のタイミング・予約の解除とリセット・重複抑止・生成時点の位置・距離と方位の境界・経路の構成を自動検証する。
敵テンプレートの3抽選結果、機種・機数の表示、1機・2機編成の完了と採点、選択テンプレート不在時の再試行、別ウィングとの独立性も模擬検証する。
この検証はゲーム内の離陸判定や AI 交戦の確認を代替しない。

| ケース | 期待結果 |
|---|---|
| 地上で生成要求 | 敵を即時生成せず、離陸待ちメッセージを表示する |
| 離陸待ち / 生成待ち中に再要求 | 予約が1件のままで、カウントを変更せず追加生成しない |
| 離陸 | 約2秒間隔の監視で検出し、20秒間は生成せず、その後に1編隊を生成する |
| 20秒の間に移動・旋回 | 生成時点の位置・機首方向を基準に生成する |
| 生成前に着地して再離陸 | カウントをリセットし、再離陸検出から20秒後に生成する |
| 予約中に死亡・離脱・スロット変更 | 予約を解除し、別機体で勝手に生成しない |
| AI 僚機だけが離陸 | プレイヤーが地上にいる間は離陸待ちを維持する |
| 全参加者が空中で生成要求 | 離陸待ちを挟まず生成する |
| 機首方位 0 / 90 / 180 / 270° と斜め方向 | 敵が機首方向から左右60°以内に出現し、距離が60～80 NMに収まる |
| 方位差 -60 / 0 / +60° と 0 / 360° 境界 | 方位が正規化され、左右60°の制限と HOT を維持する |
| 敵初期姿勢と経路 | ランダムな出現方位でも機首がこちらを向き、生成時のプレイヤー水平位置を通って出現方向の反対側20 NMへ進む |
| 高度・速度 | 15,000～30,000 ft BARO、経路指定速度が約447 knots |
| 敵テンプレート抽選 | 3編成のいずれかが生成され、デバッグ開始ログの機種・機数が実際の編成と一致する。Hostilesは画面へ出さない |
| 敵の編隊形状 | 5種類から生成ごとに1つ選び、Open の間隔で移行する。接敵前に各種類の形状を確認する |
| 実行中に再要求 | 敵が二重生成されない |
| 2機編成で敵1機だけ撃墜 | 完了表示が出ず、残機が生存している |
| 1機編成で敵1機を撃墜 | 目標達成となり、帰還待ちへ移る |
| 敵全滅 | 達成表示と帰還指示を表示し、帰還待ちの間は次の生成を抑止する |
| BLUE 飛行場・空母への帰還 | 5 knots以下を連続10秒維持し、150ポイントを一度だけ付与する |
| クリア後の墜落・死亡・脱出 | 90ポイントを一度だけ付与する |
| MP2 の2人が受注 | 受注時の搭乗者で1任務を共有し、成績と帰還評価は UCID ごとに分離する |
| 1人だけ帰還・事故・中止 | その人だけ精算し、残る参加者の任務と受注ロックを維持する |
| 全員の精算・中止 | ロックを解除し、次の受注が可能になる |
| 別ウィングが受注 | 別の敵・任務を生成し、独立して開始する。既存任務の帰還や中止は他方へ影響しない |
| 別スロットからの再受注 | 元の任務が未終了なら登録 UCID のロックで拒否する |
| AI 交戦 | ME の兵装と経路タスクを確認し、敵が探知・接敵・発射することを確かめる |
| AWACS の除外 | 敵が Hornet に交戦し、BLUE E-3A を攻撃対象として追跡・攻撃しない |
| プレイヤーの再武装 | 地上で再武装を要請し、選択した兵装を搭載できる |
| 空港・空母の単独 / MP2 スロット | 出撃地点によらず現在の搭乗者と長機を基準に開始する |
