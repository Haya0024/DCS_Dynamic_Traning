# ウィング共有任務仕様

更新日: 2026-10-04

## 現在の実装と対象

同じ DCS グループに搭乗する BLUE F/A-18C の人間プレイヤーが、1件の Intercept / SEAD / DEAD 任務を共有する。
MP2（Client ×2）、単独 Client、Client＋AI 僚機に対応する。空席や AI は参加者に数えない。
静的 Client スロットを対象とし、動的 Client スロット・複数乗員は試用対象外。
コードと模擬テストは実装済み。ユーザーから任務がゲーム内で動作しているとの報告あり。
MP2・複数ウィングの個別ケースの確認範囲は未記録。

ミッションの目標と敵は編隊で共有し、帰還評価・精算・累計は参加者の UCID ごとに管理する。
任務は1ウィングにつき同時に1件。別ウィングはそれぞれ独立した任務を同時に受注できる。
永続保存は未実装。設定と保存上の制約は [SCORING.md](SCORING.md) を参照する。

SEAD は主要レーダー破壊、または損傷＋Radar OFF連続60秒で目標達成し、共通の個別帰還評価で150／90／0ポイントを精算する。
地点選定中の `PLANNING` も受注をブロックし、同一ウィング・UCID で Intercept と SEAD を同時に受注できない。
SEADは受注時にTOO / PB・SAM・Zoneを固定し、実配置予定点とTOOの捜索点／PBの推定点を計画する。地上受注では全員の離陸後20秒で同じ計画を生成する。
距離判定は受注時の長機位置を使う。詳細は [SEAD.md](SEAD.md) を参照する。
以下の開始手順は Intercept の動作。全員離陸待ち・共有目標・個別報酬・帰還評価は3カテゴリに適用する。
Follow-on DEADは既存Siteを受注時に予約し、全員離陸でACTIVEへ移す。20秒の生成待ちはない。

## 受注と開始

1. 参加する全員が同じグループの Client スロットに搭乗する。
2. どちらかが F10 の `Dynamic Training → Generate Intercept` を選ぶ。
3. その時点の搭乗者・UCID・機体オブジェクトを参加者として固定する。
4. 全員がすでに空中なら即生成する。地上の参加者がいれば全員の離陸を待つ。
5. 全員の離陸検出から20秒後に、長機の現在位置・機首方向を基準に敵を生成する。

長機の基準は、搭乗中の参加者の機体番号が最も小さい機体。
1番機が空席なら2番機を基準に単独で開始できる。F10 の実行者を長機と推定しない。
機体番号は MOOSE `UNIT:GetNumber()` から取得し、列挙順には依存しない。
離陸判定は2秒間隔なので、全員が離陸した実時刻から生成までは約20～22秒。

途中参加者は現在の任務の参加者に追加しない。次回の受注から参加する。
生成待ち中に参加者が着地すると、編隊全体のカウントをリセットする。
生成前の参加者死亡・退出・機体変更・操縦者変更は予約全体を解除する。
個人中止で生成前に離脱した人は離陸待ちの対象から外し、残る参加者でカウントをやり直す。

## 共有目標と個別精算

Intercept は生成した敵航空機の全滅、SEAD は生成した主要レーダーの破壊または損傷＋連続60秒のRadar OFFで、未精算の参加者全員が帰還待ちに移る。
誰が破壊したかによる配分はしない。AI 僚機や別の味方による対象破壊も目標達成に含める。
報酬は1人あたり150ポイントで、2人なら各自150。編隊全体の150を分割しない。

| 結果 | 長機 | 僚機 |
|---|---:|---:|
| クリア後、2人とも帰還成功 | 150 | 150 |
| クリア後、長機は帰還・僚機は墜落／死亡／脱出 | 150 | 90 |
| クリア後、2人とも墜落／死亡／脱出 | 90 | 90 |
| 僚機がクリア前に死亡、その後長機がクリアして帰還 | 150 | 0 |
| 長機が個人中止、その後僚機がクリアして帰還 | 0 | 150 |

帰還場所と着陸確認タイマーは各自に保持する。別の BLUE 基地・空母への帰還でもよい。
現在は地上状態と5 knots以下を連続10秒確認し、空母では艦との相対速度を使う。
先に帰還を確定した人へ先に加算し、もう一人は帰還評価を継続する。
一方の事故、復行、退出、個人中止で、もう一方の評価・確定済みポイントを変更しない。

長機が失われても、未精算の僚機がいれば敵と任務を維持する。
残る参加者のうち機体番号が小さい生存機へ長機の基準を移す。
クリア前の死亡・中止は0ポイントで確定し、後の編隊クリアで遡って報酬を与えない。
全参加者の精算または個人中止が完了すると受注ロックを解除する。残敵は標準で削除し、明示RETAINのSAM Siteだけ保持する。

## 受注ブロッカー

[src/missions.lua](../src/missions.lua) が任務状態と受注ロックを保持する。
`Missions.wings[groupName]` にウィングごとの記録を保持し、単一の全体任務は使用しない。
予約または敵生成より前に `Missions.Acquire` を行う。
同じウィング名、または登録済み UCID が未終了の任務に紐づく場合は、新たな受注を拒否する。

ロックは離陸待ち・20秒待ち・戦闘中・帰還待ち・着陸確認中のすべてで保持する。
SEADも計画中・離陸待ち・20秒待ち・戦闘中・帰還待ち・着陸確認中に保持する。計画・生成の失敗、予約取消、全参加者の終了で解除する。
主要レーダーの目標を達成しても、その時点ではロックを解除しない。残る発射機も全参加者の終了まで維持する。
エミッターの完了判定は止める。全員終了後のSAMの扱いは独立したサイト管理がdispositionで決め、削除失敗中もウィングの受注ロックは解除する。
Immediate DEADは同じSEAD record内のDEAD_ACTIVE phaseで、未精算参加者に追加DEAD採点を設定する。SEADとDEADの達成時刻を分離し、両目標達成＋帰還は各自合計300、達成後事故180、DEAD未達成事故90。精算済み参加者へ遡及せず、任務数は1件。Follow-on DEADは新規DEAD recordで最寄り保持Siteを予約し、既存の個別帰還・排他を使う。
元SEADの全員終了までは保持Siteの予約を解かず、DEAD受注後もその全員終了まで別Wingの取得を拒否する。詳細は [DEAD.md](DEAD.md)。
例外として、Preserve時の登録長機がログアウトしたRETAIN SiteはSite予約だけ解除しCleanupする。元SEADの個別精算・Wing/UCIDロックは維持し、IN_USEのDEAD Siteはこの処理で削除しない。
1人だけ精算しても、そのウィングと登録 UCID のロックは解除しない。
元の参加者が全員スロットを移動してもウィングのロックを保持し、別の搭乗者による二重受注を防ぐ。
同じ UCID が別ウィングのスロットへ移っても、元の編隊が終了するまでは新たな受注を拒否する。

解除条件は全員の精算・中止、予約取消、敵生成失敗。
連打・両方の F10 からの受注でも、参加者・開始時刻・敵を二重に作らない。
BLUE 全体の1件制限は設けない。A が離陸待ち・戦闘中・帰還待ちでも、B は別の任務を受注できる。
将来の別カテゴリも同じ受注ブロッカーを利用する。

## 複数ウィングの同時実行

敵は任務ごとに `SPAWN:NewWithAlias` と受注番号を使い、`DT_INTERCEPT_<受注番号>#001` などの別名で生成する。
SEAD の別名は `DT_SEAD_<受注番号>#001`。SAM の配置失敗・中止も他のウィングへ影響させない。
`src/config.lua` の `intercept.templates` から任務ごとに敵編成を抽選する。
同じ候補を選んだ場合も敵の別名は独立する。ME のテンプレート名自体は変更しない。
再受注・生成失敗後の再試行でも受注番号を変え、同じグループ名・機体名を再利用しない。

目標達成はその任務に生成した敵の DCS オブジェクトだけを照合する。
別ウィングの敵の撃墜で、自分の目標を達成扱いにしない。
別の味方が自分の任務の敵を撃墜した場合は自分の任務の目標達成に含める。
敵の交戦指示は引き続き BLUE の Fighters / Multirole fighters が対象で、生成元ウィングへの強制攻撃にはしない。

1秒ごとの監視と事故・着陸イベントは、各任務を個別の保護呼び出しで処理する。
1件の終了・予約取消・生成失敗で、別任務のロック・敵・帰還タイマーを解除しない。
全員の終了でウィングの記録を解除してから、その任務の敵をCleanupする。明示RETAINのSiteは予約だけ解除して保持する。
処理中に記録が減っても他の任務を飛ばさないよう、監視・イベント処理は任務一覧のコピーを使う。

## F10 と中止操作

- `Mission Status`: 共通状態、長機の基準、全参加者の戦闘・帰還・精算状態を表示する。
- `Player Statistics`: 現在そのグループに搭乗する人間全員の累計を、機体名つきで表示する。
- `Abort Mission`: ウィング全体を中止する。未精算の参加者だけを0ポイントで精算する。
- `Abort Sortie: <プレイヤー名> [<機体名>]`: 指定した参加者だけを中止する。残る参加者は継続する。

F10 はグループ共有で、ボタンを押した本人の UCID は取得しない。
元のウィングに登録者が搭乗していれば、共有メニューから対象を選んで個人中止できる。
別ウィングへ移動した場合は、現在搭乗中の UCID を照合し、自分の元の出撃だけを個人中止できる。
複数人の元のウィングを別グループから全体中止することはできない。
単独任務は同じ UCID の別スロットから `Abort Mission` でも解除できる。
退出・スロット変更だけでは自動60%にせず、元の機体の事故通知または個人中止まで保留する。

状態表示・中止メニューは自分のウィングと、搭乗者 UCID に紐づく元の出撃だけを参照する。
未受注の別ウィングには `Intercept: Idle.` を表示し、他人の任務の状態・個人中止メニューを表示しない。
別スロットに元の参加者が集まり、複数の元任務が見つかる場合は各任務を状態表示し、名前・機体を指定して個人中止する。
元の任務が複数あり現在のウィング自体に任務がない場合、`Abort Mission` で任意の1件を選んで中止しない。
現在のウィング自体にも任務があれば、`Abort Mission` はそのウィングの任務を対象とする。

- [src/dead.lua](../src/dead.lua): 保持Site選定・残存対象固定・DEAD全滅判定。
- [src/scoring.lua](../src/scoring.lua): 任務ID＋UCIDごとの一度だけの精算。
- [src/recovery.lua](../src/recovery.lua): 参加者ごとの着陸確認。
- [scripts/Test-Wing.lua](../scripts/Test-Wing.lua): 結合済み本番コードによる編隊の模擬検証。
- [scripts/Test-ParallelWings.lua](../scripts/Test-ParallelWings.lua): 複数ウィングの同時受注・敵識別・独立した帰還／中止／例外処理。
- [scripts/Test-SEAD.lua](../scripts/Test-SEAD.lua): 地点選定・レーダー状態遷移・個別採点・サイトCleanup・カテゴリ間受注ブロック・中止と他ウィングの独立性。
- [scripts/Test-DEAD.lua](../scripts/Test-DEAD.lua): 同Group継承・明示保持・多Wing予約・Immediate/Follow-on DEAD・独立採点とCleanup。

`Build-Mission.ps1` の後に Lua 5.1 で `scripts/Test-Wing.lua` を実行する。
`scripts/Test-ParallelWings.lua` で複数任務の独立性を確認し、既存の `Test-Intercept.lua` と `Test-Scoring.lua` でも単独訓練の動作を確認する。
実機では MP2 の2人受注・全員離陸待ち・共有 F10・別時刻の帰還・個別事故・中止・受注拒否を確認する。
複数ウィングで同時に受注し、異なる敵名・別のカウントダウン・個別の目標達成・終了処理を確認する。
Lua は既存の埋め込みファイルへ結合するため、ME の追加トリガー登録は不要。
